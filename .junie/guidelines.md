# AutoFinderBot Development Guidelines

This document provides essential information for developers working on the AutoFinderBot project.

## Build and Configuration Instructions

### Prerequisites
- JDK 21
- Docker and Docker Compose
- Gradle 8.12.0 or later (or use the included Gradle wrapper)

### Building the Application
The project uses Gradle as the build tool. You can build the application using:

```bash
# Using Gradle wrapper
./gradlew clean build

# Using Gradle directly
gradle clean build
```

The build process includes:
- Compiling the code
- Running tests
- Generating JaCoCo test coverage reports
- Verifying test coverage meets minimum thresholds

### Configuration
The application uses environment variables for configuration, which can be set in:
- `.env` file for production
- `.env.dev` file for development

Key configuration parameters:
- `TELEGRAM_BOT_TOKEN`: Token for the Telegram Bot API
- `APP_JWT_SECRET`: Secret key for JWT authentication

### Docker Deployment
The application can be deployed using Docker Compose:

```bash
# Development environment
docker-compose -f docker-compose.yml -f docker-compose.override.yml up -d

# Production environment
docker-compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

## Testing Information

### Test Configuration
Tests use TestContainers to spin up a PostgreSQL container, so Docker must be running when executing tests.

The test configuration is defined in:
- `BaseSpringBootTest`: Sets up the database container and common test configuration
- `BaseRestApiTest`: Extends `BaseSpringBootTest` and adds REST API testing capabilities

### Running Tests
You can run tests using:

```bash
# Run all tests
./gradlew test

# Run a specific test class
./gradlew test --tests "com.example.autofinderbot.shared.StringUtilsTest"

# Run a specific test method
./gradlew test --tests "com.example.autofinderbot.shared.StringUtilsTest.testIsNullOrEmpty_WithNull_ReturnsTrue"
```

### Adding New Tests
When adding new tests:

1. **Unit Tests**: Place in the corresponding package under `src/test/java`
2. **REST API Tests**: Extend `BaseRestApiTest` to leverage the common test setup
3. **Database Tests**: Extend `BaseSpringBootTest` for database integration tests

#### Test Naming Conventions
- Test classes should be named with the suffix `Test`
- Test methods should follow the pattern `testMethodName_Scenario_ExpectedResult`
- Use suffixes `_PosTC` for positive test cases and `_NegTC` for negative test cases

#### Example Test
Here's a simple example of a test class:

```java
package com.example.autofinderbot.shared;

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

public class StringUtilsTest {

    @Test
    void testIsNullOrEmpty_WithNull_ReturnsTrue() {
        // Arrange
        String input = null;
        
        // Act
        boolean result = StringUtils.isNullOrEmpty(input);
        
        // Assert
        assertTrue(result, "null string should be considered empty");
    }
    
    // Additional test methods...
}
```

### Test Coverage Requirements
The project enforces minimum test coverage thresholds:
- 80% line coverage
- 50% branch coverage
- 100% method coverage

JaCoCo reports are generated in `build/reports/jacoco/test/html/index.html`.

## Additional Development Information

### Code Style
- The project follows standard Java code style conventions
- Use final classes for utility classes with private constructors
- Document public APIs with JavaDoc

### Database Migrations
- Database schema changes are managed with Liquibase
- Main changelog: `src/main/resources/db/changelog/main/db.changelog-main.yaml`
- Test changelog: `src/test/resources/db/changelog/test/db.changelog-test.yaml`

### Authentication
- The application uses JWT for authentication
- JWT tokens are generated by the `/api/auth/login` endpoint
- Include the token in the Authorization header as a Bearer token

### REST API Testing
The project includes utilities for testing REST APIs:
- `TestRequestSender`: Sends HTTP requests with different authentication contexts
- `JwtTestHelper`: Handles JWT token generation for tests

Example usage:
```java
@Autowired
TestRequestSender testRequestSender;

@Test
void testEndpoint() {
    ResponseEntity<SomeResponse> response = testRequestSender.asAdmin(
        "/api/endpoint", GET, requestBody, SomeResponse.class);
    
    assertThat(response.getStatusCode()).isEqualTo(OK);
    // Additional assertions...
}
```
